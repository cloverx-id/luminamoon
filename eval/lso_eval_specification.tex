\begin{abstract}
\noindent
This specification defines the \textbf{Lumina Moon Standard Optimizer Evaluation Methodology (LSO-Eval v1.1.1)}, a practical procedure for testing and benchmarking neural network optimizers across CPU and GPU implementations. LSO-Eval divides verification into four sequential stages, moving from fast mathematical checks on CPU to full-scale model training on GPU: (I) Algebraic Safety and Numerical Precision Checks, (II) Synthetic Test Functions, Backend Consistency, and Checkpointing, (III) Short-Run Proxy Model Screening, and (IV) Large-Scale Pre-Training Evaluation with Train--Validation Deduplication and Two-Class Acceptance Criteria. Beyond the core language modeling pipeline, \textbf{V-Eval} tests computer vision architectures across low-, medium-, and full-resolution datasets, and \textbf{D-Eval} guards against regressions between software releases. Both Stage IV and V-Eval define a single-GPU \textit{Standard Setup} alongside a multi-GPU \textit{Extended Setup} so the same benchmark rules scale from local workstations to cluster runs. All rules in Sections 1--7 are algorithm-agnostic.
\end{abstract}

\section{Scope, Principles, and Evaluation Stages}

\subsection{Objectives and Scope}
\noindent
LSO-Eval provides a shared testing checklist for optimization algorithms and CPU/GPU compute kernels. Because the procedure does not depend on any single update rule, its specification version (v1.1.1) is tracked separately from individual optimizer releases. The methodology focuses on four practical goals:

\begin{enumerate}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Save Compute Resources:} Catch division-by-zero risks, numerical overflow or underflow, and narrow hyperparameter ranges on CPU before spending GPU hours.
    \item \textbf{Separate Mathematical Issues from Kernel Bugs:} Check symbolic update equations, function approximations, low-precision rounding, and parallel compute kernels in separate steps so the cause of any failure is easy to locate.
    \item \textbf{Verify Backend and Multi-GPU Consistency:} Confirm that multithreaded CPU kernels, SIMD vector paths, GPU compute shaders or kernels, sharded multi-GPU reductions, and Python bindings match a single-threaded scalar reference within defined numerical tolerances.
    \item \textbf{Jointly Evaluate Model Quality and Optimizer Memory:} Pair validation metrics with isolated optimizer state memory---measured separately from model weights, gradients, and activations---using distinct acceptance criteria for two-buffer (full-state) and single-buffer (compressed-state) designs.
\end{enumerate}

\subsection{Evaluation Stages}
\noindent
LSO-Eval is organized into a fast CPU verification phase (\textbf{Stages I and II}) and a GPU training phase (\textbf{Stages III, IV, and V-Eval}), supplemented by version regression tests (\textbf{D-Eval}) as summarized in Table~\ref{tab:pipeline}. The CPU stages act as an automated gate that catches mathematical or kernel-parity defects in under a minute before any GPU budget is spent. The GPU stages then evaluate training stability, memory footprint, and throughput from single-GPU setups up to multi-node clusters. Pipeline execution is strictly sequential: if a candidate fails any stage, evaluation halts immediately until the underlying issue is resolved.

\section{Stage I: Algebraic Safety \& Numerical Precision Checks}
\noindent
Before running a single training step, Stage I verifies the mathematical soundness and finite-precision behavior of an update rule. We express the update equations symbolically to prove algebraic invariants with an SMT solver, then test finite-precision approximations and rounding behavior numerically.

\subsection{General SMT Safety Checklist (Z3 Solver)}
\noindent
An update rule $u_t(\theta, g, m, v)$ must not produce NaNs, infinities, or division by zero under valid hyperparameter settings. Stage I verifies seven algebraic conditions using the Z3 Theorem Prover~\cite{demoura2008z3} by testing the \textbf{negation} of each property and confirming that the solver returns \texttt{UNSAT} (unsatisfiable):

\begin{enumerate}[label=\textbf{Q\arabic*.}, leftmargin=2.4em, itemsep=0.45em]
    \item \textbf{No Division by Zero:} For all real gradients $g \in \mathbb{R}$, momentum states $m \in \mathbb{R}$, non-negative second-moment states $v \ge 0$, and $\epsilon > 0$, prove that the update denominator $\mathcal{E}$ (or variance divisor $\sigma$) remains strictly positive ($\mathcal{E} > 0$). Negated query: $\mathcal{E} \le 0$.

    \item \textbf{Update Magnitude \& Trust-Region Bounds:} Confirm that the normalized update $u_t$ and any optional step clipping satisfy the bounds of the optimizer's category:
    \begin{itemize}[leftmargin=1.5em, itemsep=0.25em]
        \item \textit{Profile A (Normalized / Bounded-Update Optimizers, e.g., Lion~\cite{chen2023lion} and bounded-ratio designs):} Unit-bounded update magnitude $|u_t| \le 1.0$, positive coordinate clipping limit $B_i > 0$, and radial clipping lower bound $R \ge r_{\text{bound}}$~\cite{brock2021nfnet} when adaptive clipping is enabled.
        \item \textit{Profile B (Variance-Adaptive Optimizers, e.g., AdamW~\cite{loshchilov2019adamw}, AdaBelief~\cite{zhuang2020adabelief}, ADOPT~\cite{taniguchi2024adopt}):} Lower-clamped variance divisor $\sigma_{\text{clamped}} \ge \epsilon_{\min} > 0$ and finite step size as $g \to 0$.
        \item \textit{Profile C (Matrix-Preconditioned / Subspace Optimizers, e.g., Shampoo~\cite{gupta2018shampoo}, GaLore~\cite{zhao2024galore}):} Bounded matrix operator norm $\|U_t\|_2 \le C$ and positive minimum singular value $\sigma_{\min}(P) > 0$ for the preconditioner.
    \end{itemize}

    \item \textbf{Radial Scaling \& Alignment Mask Bounds:} When radial norm scaling $S(r)$ is applied for $r \ge 0$, prove that $0 < S(r) \le 1.0$. When cautious gradient-alignment masking~\cite{liang2026cautious} is used with mask $\mathcal{M}_t = \mathbb{I}(u_t \odot g_t > 0)$ and density floor $c_{\min} \in (0, 1]$, prove that the rescaling factor $s_{\text{cautious}} = 1/\mathrm{clip}(\mathrm{mean}(\mathcal{M}_t), c_{\min}, 1.0)$ stays within $[1.0, 1/c_{\min}]$.

    \item \textbf{Half-Precision Floor \& Overflow Bounds:} Under 16-bit execution (\texttt{float16} or \texttt{bfloat16}), verify that any lower clipping floor stays at or above the IEEE 754 FP16 minimum positive normal threshold ($\text{floor}_{\text{sub}} = 2^{-14} \approx 6.1035 \times 10^{-5}$) and that any FP16 second-moment state is clamped below the FP16 maximum representable value ($65,504.0$).

    \item \textbf{Descent Alignment:} Prove that starting from zero momentum ($m_0 = 0$) for any non-zero gradient $g_t \neq 0$, the initial update satisfies $\langle u_0, g_t \rangle > 0$, and that under cautious alignment masking~\cite{liang2026cautious} ($\mathcal{M}_t = \mathbb{I}(u_t \odot g_t > 0)$), the gradient-driven update prior to decoupled weight decay satisfies $\langle \delta_{\text{cautious}}, g_t \rangle \ge 0$ (with strict positivity whenever $\mathcal{M}_t \neq 0$).

    \item \textbf{Weight Decay Contraction:} For learning rate $\eta \in (0, 0.05]$, decoupled weight decay~\cite{loshchilov2019adamw} $\lambda_{\text{wd}} \in [0, 1.0]$, and effective shrinkage $\eta\lambda_{\text{wd}} < 1.0$, prove that the multiplicative decay factor satisfies $(1 - \eta\lambda_{\text{wd}}) \in (0, 1]$.

    \item \textbf{Bias Correction Positivity:} For all steps $t \ge 1$ and decay rates $\beta_1, \beta_2 \in (0, 1)$ (encoded via inductive step bounds $\hat{\beta}_{1,t} \in [1-\beta_1, 1)$ and $\hat{\beta}_{2,t} \in [1-\beta_2, 1)$), prove that first- and second-moment bias-correction factors remain strictly positive ($\text{bc}_1 = \hat{\beta}_{1,t} > 0, \text{bc}_2 = \hat{\beta}_{2,t} > 0$).
\end{enumerate}

\subsection{Symbolic Limits, Function Approximation \& Rounding Checks}
\noindent
Alongside Z3 verification, Stage I includes four analytical and finite-precision evaluations:

\begin{enumerate}[label=\textbf{S\arabic*.}, leftmargin=2.4em, itemsep=0.45em]
    \item \textbf{Large-Gradient Limit Check:} Compute the symbolic limit of the normalized update $u_t$ in SymPy~\cite{meurer2017sympy} as the gradient magnitude grows large along a coupled update step:
    \begin{equation}
        u_\infty = \lim_{|g| \to \infty} u_t(m, g).
    \end{equation}
    \textbf{Acceptance Rule:} Profile A optimizers must satisfy $|u_\infty| \le 1.0$. Profile B and C optimizers (evaluating coupled second-moment updates or active step clipping for lagged-variance rules~\cite{taniguchi2024adopt}) must remain finite without numerical overflow.

    \item \textbf{Piecewise Transition Continuity ($C^0/C^1$):} When an algorithm switches between piecewise expressions at a small cutoff $r_{\text{thresh}}$ (such as substituting $1.0$ for $\tanh(r)/r$ near zero), verify that the $C^0$ boundary value jump $\Delta_{\text{jump}}$ is smaller than single-precision machine epsilon ($\epsilon_{\text{FP32}} \approx 1.19 \times 10^{-7}$) with bounded $\mathcal{O}(r_{\text{thresh}})$ first-derivative transition.

    \item \textbf{Function Approximation Accuracy (When Applicable):} Kernels that replace standard math functions ($\tanh$, $\mathrm{erf}$, or $1/\sqrt{x}$) with rational or polynomial approximations~\cite{molina2020pade} for SIMD or GPU execution must be evaluated across their input range ($500,000$ test points) against IEEE 754 \texttt{float32}. \textbf{Acceptance Rule:} The maximum absolute error must stay below $\|f_{\text{approx}}(x) - f_{\text{exact}}(x)\|_\infty < 1.5 \times 10^{-6}$, while preserving odd/even symmetry and NaN propagation.

    \item \textbf{Unbiased Stochastic Rounding (When Applicable):} Optimizers that write parameters or states into 16-bit or 8-bit tensors via stochastic rounding~\cite{gupta2015limited,zamirai2021revisiting} are tested with $N = 200,000$ samples across both normal ($[10^{-3}, 10^{-1}]$) and FP16 subnormal ($[10^{-5}, 6.1 \times 10^{-5}]$) magnitudes. Practical unbiasedness ($H_0: |\mathbb{E}[\mathcal{Q}_{\text{SR}}(x)] - x| \ge \delta_{\text{tol}}(x)$) is evaluated with Two One-Sided Tests (TOST) at equivalence tolerance $\delta_{\text{tol}}(x) = \max(10^{-6}, 2.5 \times 10^{-3}\,\text{ULP}(x))$ alongside Monte Carlo standard-error bounds. \textbf{Acceptance Rule:} Sample mean bias must satisfy $|\mu_{\mathcal{Q}} - x| < \delta_{\text{tol}}(x)$ with $p_{\text{TOST}} < 0.01$ and standardized error $|(\mu_{\mathcal{Q}} - x)/\text{SE}| < 3.0$ (or $|\mu_{\mathcal{Q}} - x| \le 0.1\,\text{ULP}(x)$ in subnormal regimes).
\end{enumerate}

\section{Stage II: Synthetic Test Functions, Backend Consistency, and Checkpointing}
\noindent
Stage II evaluates optimization trajectories on low-dimensional analytical surfaces, measures sensitivity to hyperparameter perturbations, verifies numerical consistency across CPU, GPU, and sharded multi-GPU backends, and validates checkpoint serialization.

\subsection{Synthetic Benchmark Functions}
\noindent
Candidate update rules are compared against standard baselines (such as AdamW~\cite{loshchilov2019adamw} in FP32 Master and Native BF16 modes) across five classical test functions~\cite{jamil2013survey} using the runner in Listing~\ref{lst:stage2_runner}:

\begin{enumerate}[label=\textbf{B\arabic*.}, leftmargin=2.4em, itemsep=0.45em]
    \item \textbf{Ill-Conditioned Quadratic Bowl ($\kappa \ge 1000$):}
    \begin{equation}
        f(w_0, w_1) = \frac{1}{2}\left(w_0^2 + 1000w_1^2\right), \qquad w^{(0)} = [10.0, 1.0]^\top.
    \end{equation}
    \textbf{Purpose:} Checks whether the optimizer dampens oscillations along the steep axis $w_1$ without stalling along the flat axis $w_0$.

    \item \textbf{Non-Convex Rosenbrock Curved Valley~\cite{jamil2013survey,rosenbrock1960automatic}:}
    \begin{equation}
        f(w_0, w_1) = (1 - w_0)^2 + 100(w_1 - w_0^2)^2, \qquad w^{(0)} = [-1.5, 2.0]^\top.
    \end{equation}
    \textbf{Purpose:} Evaluates how well the optimizer follows a curved valley where the gradient direction changes continuously.

    \item \textbf{Convergence Under Gradient Noise:} Runs the quadratic bowl with additive Gaussian noise $\tilde{g}_t = \nabla f(w_t) + \mathcal{N}(0, \sigma^2 I)$ at $\sigma = 1.0$. \textbf{Purpose:} Measures steady-state error near the optimum when gradients are noisy.

    \item \textbf{Multimodal Rastrigin Local-Minima Escape~\cite{rastrigin1974systems}:}
    \begin{equation}
        f(w_0, w_1) = 20 + \sum_{i=0}^{1}\left(w_i^2 - 10\cos(2\pi w_i)\right), \qquad w^{(0)} = [2.5, 2.5]^\top.
    \end{equation}
    \textbf{Purpose:} Tests whether momentum helps parameters move past shallow local minima toward the global minimum at $(0, 0)$.

    \item \textbf{High-Dimensional Saddle Point Escape ($N \ge 100$):}
    \begin{equation}
        \begin{gathered}
            f(w) = \frac{1}{2}\sum_{i=1}^{N}\lambda_i w_i^2 + \frac{1}{4}\sum_{i=1}^{N} w_i^4, \qquad f^* = -\frac{1}{4}\sum_{\lambda_i < 0}\lambda_i^2, \\
            \lambda_i \in [-1.0, 1000.0], \qquad w_i^{(0)} = 10^{-4}.
        \end{gathered}
    \end{equation}
    \textbf{Purpose:} Measures how quickly the optimizer escapes saddle points at the origin combining negative and large positive eigenvalues (spaced linearly via \texttt{np.linspace(-1.0, 1000.0, N)}) toward the global minimum $f^* < 0$ (attained at $w_i^* = \pm\sqrt{-\lambda_i}$ for $\lambda_i < 0$ and $w_i^* = 0$ for $\lambda_i \ge 0$).
\end{enumerate}

\begin{lstlisting}[caption={Standard LSO-Eval Stage II: General Synthetic Function Test Runner (v1.1.1)}, label={lst:stage2_runner}]
import numpy as np

def run_synthetic_benchmark(loss_fn, grad_fn, step_fn, w_init, f_star=0.0,
                            lr=0.01, max_steps=2000, tol=1e-5,
                            noise_std=0.0, seed=1337):
    rng = np.random.default_rng(seed)
    w = np.array(w_init, dtype=np.float64)
    state = {}
    current_loss = loss_fn(w)

    for t in range(1, max_steps + 1):
        g = grad_fn(w)
        if noise_std > 0.0:
            g = g + rng.normal(0.0, noise_std, size=g.shape)
        w, state = step_fn(w, g, state, lr, t)
        current_loss = loss_fn(w)
        curr_gap = abs(current_loss - f_star)
        if np.isnan(w).any() or np.isinf(w).any() or curr_gap > 1e8:
            return t, curr_gap, "DIVERGED"
        if curr_gap < tol:
            return t, curr_gap, "CONVERGED"
    return max_steps, abs(current_loss - f_star), "MAX_STEPS"
\end{lstlisting}

\subsection{Hyperparameter Sensitivity Checks}
\noindent
Practical optimizers must converge reliably without brittle hyperparameter tuning~\cite{loshchilov2019adamw}. We evaluate robustness against three criteria:

\begin{enumerate}[label=\textbf{P\arabic*.}, leftmargin=2.4em, itemsep=0.35em]
    \item \textbf{One-at-a-Time Parameter Sweep:} Keep default settings fixed and vary each hyperparameter across at least 5 values spanning an order of magnitude.
    \item \textbf{Analytical Parameter Bounds:} Whenever a coefficient controls a stability condition or balances competing update terms, derive its valid range analytically where possible and validate inputs when initializing the optimizer.
    \item \textbf{Parameter Stability Range:} Perturbing auxiliary hyperparameters by $\pm 30\%$ around their defaults must not increase the convergence step count on the $\kappa = 1000$ quadratic benchmark by more than $15\%$.
\end{enumerate}

\subsection{Feature Combinations, Single-Pass Reductions \& Backend Consistency}
\noindent
Multi-backend optimizer libraries must produce consistent results across configuration flags, hardware targets, and sharded multi-GPU modes:

\begin{enumerate}[label=\textbf{A\arabic*.}, leftmargin=2.4em, itemsep=0.4em]
    \item \textbf{Feature Combination Stability:} Every supported combination of state buffer modes, step-clipping options~\cite{brock2021nfnet}, and alignment masks~\cite{liang2026cautious} must produce finite, convergent updates.

    \item \textbf{Single-Pass Reduction Consistency (When Applicable):} Kernels that fuse global norm or mask reductions into a single memory pass~\cite{dao2022flashattention,tillet2019triton} by reading exponential moving average (EMA) statistics from step $t-1$ must converge within $+1.0\%$ of the step count of an exact two-pass reduction on the $\kappa = 1000$ benchmark.

    \item \textbf{Cross-Backend \& Sharded Parity:}
    \begin{itemize}[leftmargin=1.5em, itemsep=0.25em]
        \item \textit{Parallel Reduction Parity:} Multithreaded CPU reductions must use deterministic pairwise or tree summation so outputs match single-threaded scalar execution ($\text{atol} = 0.0$).
        \item \textit{PRNG \& Rounding Parity:} Vectorized SIMD PRNG and stochastic rounding routines must match the scalar reference bit-for-bit ($\text{atol} = 0.0$).
        \item \textit{Multi-Step Update Parity ($N = 131,072$, 5 steps):} Across supported floating-point formats (FP32, BF16, FP16), vectorized CPU and GPU compute backends must agree with the scalar reference within $\text{atol} \le 10^{-5}$ for FP32 and $\text{atol} \le 2 \times 10^{-2}$ for BF16/FP16.
        \item \textit{Sharded vs.\ Unsharded Parity (FSDP / ZeRO):} When an optimizer computes tensor-wide or layer-wise reductions (such as cautious alignment mask density $\bar{m}_t$~\cite{liang2026cautious} or radial norm clipping~\cite{brock2021nfnet}) under Fully Sharded Data Parallel (FSDP) or ZeRO parameter sharding, local reduction sums must be synchronized across ranks via \texttt{all\_reduce} so sharded parameter updates match single-device unsharded updates within $\text{atol} \le 10^{-6}$ (FP32).
        \item \textit{Python Binding Parity:} NumPy and PyTorch bindings must produce identical parameter tensors when given identical inputs and seeds.
    \end{itemize}
\end{enumerate}

\subsection{Checkpoint Saving and Loading Check}
\noindent
Subtle state-serialization bugs can silently corrupt resumed training runs or bloat checkpoints with temporary workspace buffers. Every candidate must pass the \textbf{Checkpoint Roundtrip Test} (Listing~\ref{lst:checkpoint_test}) on both \texttt{float32} and \texttt{bfloat16} models. The test enforces three guarantees: (1) temporary coalescing or staging buffers are stripped prior to \texttt{state\_dict()} export without corrupting the live optimizer instance, (2) per-step scratch accumulators are zeroed out on save while \texttt{float32} master weights and scratchpads retain their exact \texttt{float32} dtype upon \texttt{load\_state\_dict()} (preventing PyTorch's default state-casting from downcasting them to \texttt{bfloat16}), and (3) training resumed from a checkpoint matches an uninterrupted run bit-for-bit ($\text{atol} = 0.0$).

\begin{lstlisting}[caption={Standard LSO-Eval Stage II: Checkpoint Roundtrip \& State Cleanup Test (v1.1.1)}, label={lst:checkpoint_test}]
import copy, io, torch, torch.nn as nn

def verify_checkpoint_integrity(optimizer_cls, opt_configs=None,
                                forbidden_keys=(), zeroed_scratch_indices=(0, 1, 2)):
    torch.manual_seed(42)
    if opt_configs is None:
        opt_configs = [{"lr": 1e-3}]
    default_forbidden = (
        "p_contig", "exp_avg_contig", "exp_avg_sq_contig",
        "mp_contig", "_plan", "_contig_step"
    )
    all_forbidden = set(default_forbidden).union(forbidden_keys)

    for dtype in (torch.float32, torch.bfloat16):
        for cfg in opt_configs:
            model_cont = nn.Sequential(
                nn.Linear(10, 20), nn.ReLU(), nn.Linear(20, 2)
            ).to(dtype=dtype)
            model_save = copy.deepcopy(model_cont)
            model_res = copy.deepcopy(model_cont)
            opt_cont = optimizer_cls(model_cont.parameters(), **cfg)
            opt_save = optimizer_cls(model_save.parameters(), **cfg)
            batches = [
                (torch.randn(4, 10, dtype=dtype), torch.tensor([0, 1, 0, 1]))
                for _ in range(6)
            ]

            for i in range(5):
                x, y = batches[i]
                rng_snap = torch.get_rng_state()
                for m, opt in ((model_cont, opt_cont), (model_save, opt_save)):
                    torch.set_rng_state(rng_snap)
                    loss = nn.CrossEntropyLoss()(m(x).float(), y)
                    opt.zero_grad(); loss.backward(); opt.step()

            model_res.load_state_dict(copy.deepcopy(model_save.state_dict()))
            buffer = io.BytesIO()
            torch.save(opt_save.state_dict(), buffer); buffer.seek(0)
            opt_loaded = optimizer_cls(model_res.parameters(), **cfg)
            state_dict = torch.load(buffer, weights_only=False)
            opt_loaded.load_state_dict(state_dict)

            for p_state in state_dict["state"].values():
                for k in all_forbidden:
                    assert k not in p_state, f"Leaked key '{k}' in state_dict!"
                if "scratch" in p_state and zeroed_scratch_indices:
                    sc = p_state["scratch"]
                    for idx in zeroed_scratch_indices:
                        assert float(sc[idx]) == 0.0

            for p in model_res.parameters():
                st = opt_loaded.state[p]
                if "scratch" in st:
                    assert st["scratch"].dtype == torch.float32
                if "master_param" in st:
                    assert st["master_param"].dtype == torch.float32

            x_last, y_last = batches[5]
            rng_snap = torch.get_rng_state()
            for m, opt in ((model_cont, opt_cont), (model_save, opt_save), (model_res, opt_loaded)):
                torch.set_rng_state(rng_snap)
                loss = nn.CrossEntropyLoss()(m(x_last).float(), y_last)
                opt.zero_grad(); loss.backward(); opt.step()

            for p_c, p_s, p_r in zip(model_cont.parameters(), model_save.parameters(), model_res.parameters()):
                torch.testing.assert_close(p_c, p_s, rtol=0.0, atol=0.0)
                torch.testing.assert_close(p_c, p_r, rtol=0.0, atol=0.0)
    return True
\end{lstlisting}

\section{Stage III: Short-Run Proxy Model Screening}
\noindent
Stage III evaluates candidate optimizers on a compact neural network proxy before committing to multi-hour GPU experiments. This screening phase filters out unstable learning rates and catches low-precision mantissa underflow early.

\subsection{Proxy Model Selection, Multi-Seed Protocol \& Step Budget}
\noindent
Screening runs use a small proxy model sharing the core building blocks of the target architecture (for instance, a 4-layer causal Transformer using RoPE~\cite{su2024roformer}, SwiGLU MLP layers, and RMSNorm~\cite{zhang2019rmsnorm}):

\begin{enumerate}[label=\textbf{M\arabic*.}, leftmargin=2.4em, itemsep=0.35em]
    \item \textbf{Step Limit:} Runs are budgeted at $5\%$ to $15\%$ of a full training schedule (typically $500$ to $2,000$ steps).
    \item \textbf{Batch Size Diversity:} Each candidate is tested at two effective batch sizes ($1\times$ micro-batch and $4\times$ gradient-accumulated batch) to verify stability across different gradient noise regimes~\cite{taniguchi2024adopt}.
    \item \textbf{Matched Schedule \& Gradient Clipping:} All tested optimizers share an identical schedule: linear warmup over the first $5\%$ of steps followed by cosine decay (or Warmup-Stable-Decay, WSD) to $5\%$ of the peak learning rate. If external global gradient norm clipping (\texttt{max\_grad\_norm}) is used, the same threshold (e.g., $1.0$) must be applied before \texttt{opt.step()} across all runs.
    \item \textbf{Multi-Seed Statistical Reporting:} Because short proxy runs take only minutes, each configuration is evaluated across at least 3 random seeds (e.g., $\text{seed} \in \{42, 1337, 2026\}$), reporting $\text{mean} \pm \text{std}$ (or median) final loss alongside the percentage of unstable or diverged trials.
\end{enumerate}

\subsection{Early Stopping \& Rejection Criteria}
\noindent
A candidate configuration fails Stage III if it triggers any of three failure conditions:

\begin{enumerate}[label=\textbf{F\arabic*.}, leftmargin=2.4em, itemsep=0.45em]
    \item \textbf{Out-of-Range Update-to-Weight Ratio:} Track the layer-wise relative parameter step norm across weight matrices with $\text{ndim} \ge 2$ (excluding singleton-broadcasted vectors with $\text{ndim} > 2$ and \texttt{param.squeeze().ndim} $\le 1$):
    \begin{equation}
        R_{t,l} = \frac{\|\Delta\theta_{t,l}\|_2}{\max(\|\theta_{t,l}\|_2, 10^{-3})}, \qquad \Delta\theta_{t,l} = \theta_{t,l} - \theta_{t-1,l}.
    \end{equation}
    This check measures the committed post-update parameter difference $\Delta\theta_{t,l}$, omits 1D biases, normalization scales, and singleton-broadcasted vectors, and logs backbone matrices separately from token embeddings and the final output head~\cite{brock2021nfnet}. \textbf{Rejection Rule:} A run is rejected if $R_{t,l} > 0.10$ on any matrix layer $l$ after warmup (step size too large) or if $R_{t,l} < 10^{-7}$ during active training ($t > t_{\text{warmup}}$ and $\eta_t \ge 0.1\eta_{\max}$, indicating stalled updates).

    \item \textbf{Unrecovered Loss Spikes:} If the exponential moving average ($\text{EMA}, \alpha = 0.99$) training loss rises by more than $0.5$ nats above its prior minimum and fails to recover below that threshold (or recover at least $50\%$ of the spike excursion) within $50$ consecutive steps, the trial is rejected.

    \item \textbf{BF16/FP16 Rounding Underflow \& Update Cancellation:} Compare the final EMA training loss of the native 16-bit (\texttt{bfloat16} or \texttt{float16}) trial against a matched reference run in \texttt{float32} precision~\cite{gupta2015limited,zamirai2021revisiting}:
    \begin{equation}
        \Delta\mathcal{L}_{\text{stall}} = \mathcal{L}_{\text{EMA}}^{(\text{BF16/FP16})}(T) - \mathcal{L}_{\text{EMA}}^{(\text{FP32-Ref})}(T).
    \end{equation}
    Following Zamirai et al.~\cite{zamirai2021revisiting}, implementations may also log the \textit{16-bit Update Cancellation Rate}---the fraction of non-zero updates $\delta_{t,i} \neq 0$ where $\theta_{t+1,i} == \theta_{t,i}$ after 16-bit addition because $|\Delta\theta_{t,i}| = |\eta_t\delta_{t,i}| < \frac{1}{2}\text{ULP}(\theta_{t,i})$. \textbf{Rejection Rule:} A loss gap of $\Delta\mathcal{L}_{\text{stall}} \ge 0.25$ nats indicates significant mantissa truncation and results in rejection.
\end{enumerate}

\subsection{Learning Rate \& Clipping Grid}
\noindent
Candidates are swept across a learning rate grid ($\eta \in [3 \times 10^{-4}, 10^{-2}]$) covering two training regimes:
\begin{itemize}[leftmargin=1.8em, itemsep=0.25em]
    \item \textbf{Long-Run Setting ($> 20\text{k}$ steps):} Moderate learning rates ($\eta \in [3 \times 10^{-4}, 8 \times 10^{-4}]$, $\lambda_{\text{wd}} = 8 \times 10^{-2}$) intended for extended pre-training schedules.
    \item \textbf{Short-Run Setting ($< 10\text{k}$ steps):} Higher learning rates ($\eta = 10^{-2}$) paired with coordinate or radial step clipping~\cite{brock2021nfnet}.
\end{itemize}

\section{Stage IV: Large-Scale Pre-Training Evaluation}
\noindent
Stage IV benchmarks candidate optimizers on language model pre-training across two schedule lengths and two hardware scale tiers:

\begin{enumerate}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Stage IV-A (Medium-Length Run):} Runs of $2,500$ to $5,000$ steps at sequence length $512$ with gradient accumulation (reference: $8\times$, $4,096$ tokens/step), measuring isolated optimizer VRAM, median step time, token throughput, and held-out validation loss and perplexity.
    \item \textbf{Stage IV-B (Full-Schedule \& Extended-Context Run):} Longer training runs ($\ge 20,000$ steps at sequence length $\ge 2,048$) testing convergence through full cosine or Warmup-Stable-Decay (WSD) learning rate decay.
\end{enumerate}

\noindent
\textbf{Standard Setup (Single-GPU) vs.\ Extended Setup (Multi-GPU / Cluster):} To keep LSO-Eval accessible to single-GPU researchers while scaling cleanly to multi-node clusters, Stage IV defines two validation tiers:
\begin{itemize}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Standard Setup (Single-GPU):} Uses a deduplicated held-out validation split of $N_{\text{eval}} \ge 450,000$ tokens (reference default: $880 \times 512 = 450,560$ tokens in Stage IV-A and $220 \times 2,048 = 450,560$ tokens in Stage IV-B) with a matched deterministic seed (\texttt{seed=42}).
    \item \textbf{Extended Setup (Multi-GPU / Cluster):} Multi-node runs spanning $10\text{B}$ to $350\text{B}+$ tokens~\cite{liang2026cautious,penedo2024fineweb} use a two-tier validation schedule. During training, periodic validation runs on $450\text{k}$--$5\text{M}$ deduplicated tokens every $N$ steps to monitor loss curves with minimal overhead. At the end of training, models are evaluated on $10\text{M}$--$100\text{M}+$ held-out tokens across diverse text and code corpora (such as Paloma~\cite{magnusson2024paloma}, C4, WikiText-103, and PG-19~\cite{yang2024gla}), paired with zero-shot downstream benchmarks (\texttt{MMLU}, \texttt{ARC}, \texttt{HellaSwag}, \texttt{PIQA}, \texttt{WinoGrande}, \texttt{OpenBookQA}, and \texttt{LAMBADA})~\cite{liang2026cautious,penedo2024fineweb,yang2024gla}.
\end{itemize}

\subsection{Data Deduplication, Domain Mixing, and Sequence Packing}
\noindent
Streaming pre-training benchmarks require clean data preparation so validation overlap, domain block ordering, and padding waste do not distort comparisons across optimizers:

\begin{enumerate}[label=\textbf{D\arabic*.}, leftmargin=2.4em, itemsep=0.4em]
    \item \textbf{Deterministic Document Hash Logging:} Every document included in the held-out validation split ($N_{\text{eval}} \ge 450,000$ tokens in Standard Setup; $\ge 10\text{M}$ tokens in Extended Setup) is hashed using a fast 64-bit non-cryptographic hash (reference default: 64-bit XXH3 recorded in a persistent \texttt{.dedup} hash log file).
    \item \textbf{Cross-Context Token Multiset Check:} When validation is configured across different sequence lengths (for example, $880 \times 512 = 450,560$ tokens in Stage IV-A and $220 \times 2,048 = 450,560$ tokens in Stage IV-B), the sorted token multisets are verified to be identical so evaluation corpora remain strictly matched.
    \item \textbf{Stream Offset \& Hash Filtering:} Training data streams advance past the raw records reserved for validation (\texttt{skip\_raw\_items}) and load the validation hash set prior to step 1, dropping any training document whose hash matches the validation set~\cite{penedo2024fineweb}.
    \item \textbf{Weighted Multi-Domain Interleaving (No Block Concatenation):} When pulling from $K$ text domains $D_1, \dots, D_K$ with mixture weights $\mathbf{p} = (p_1, \dots, p_K)$ ($\sum_{k=1}^{K} p_k = 1$), streams are combined via seeded weighted interleaving (such as multinomial sampling or windowed quotas) rather than concatenating datasets sequentially. This keeps the domain mixture stationary across warmup, peak learning rate, and decay.
    \item \textbf{Two-Step Streaming Shuffle:} Streaming loaders apply \textit{file-level shuffling} (permuting shard order via \texttt{seed + epoch}) followed by \textit{document-level shuffling} in an in-memory reservoir buffer ($B_{\text{shuf}} \ge 10,000$ documents, filled before step 1) so adjacent documents within a packed sequence come from different shards and domains.
    \item \textbf{EOD-Delimited Sequence Packing \& Asynchronous Transfer:} Instead of padding short documents with \texttt{<PAD>} tokens, tokenized documents are terminated with an explicit End-of-Document token (\texttt{EOD}/\texttt{EOS}), concatenated into a continuous stream, and sliced into dense $(B, L)$ blocks with $100\%$ token utilization. When using variable-length FlashAttention~\cite{dao2022flashattention}, loaders pass cumulative sequence offsets (\texttt{cu\_seqlens}) and reset position indices per document. Batches are staged in page-locked host memory and transferred asynchronously to the GPU.
\end{enumerate}

\subsection{Measuring Optimizer Memory, Step Time, and Runtime Environment}
\noindent
All candidate and baseline runs must execute on identical hardware with matched seeds, batch order, and context lengths. To keep timing and memory numbers reproducible, every Stage IV report must document the hardware and software environment: GPU model, interconnect, and VRAM capacity, GPU driver and compute runtime versions (CUDA, ROCm, or Vulkan), framework and compiler versions (e.g., PyTorch, Triton, Rust/C++ toolchain), and the global random seed(s).

Following prior work on memory-efficient optimizers (8-bit Optimizers~\cite{dettmers2022eightbit} and GaLore~\cite{zhao2024galore}), Stage IV separates peak active tensor memory (\texttt{torch.cuda.max\_memory\_allocated()}) into the fixed model/activation baseline $\text{VRAM}_{\text{base}}$ and the \textbf{Isolated Optimizer Memory} $\text{VRAM}_{\text{opt}}$ (Table~\ref{tab:stage4_metrics}):
\begin{equation}
    \text{VRAM}_{\text{peak}} = \underbrace{W_{\text{model}} + G_{\text{grad}} + A_{\text{ctx}}}_{\text{Fixed Model \& Activation Baseline } (\text{VRAM}_{\text{base}})} + \underbrace{\text{VRAM}_{\text{opt}}}_{\text{Isolated Optimizer State \& Master Copy}}.
\end{equation}
Because \texttt{max\_memory\_allocated()} measures active tensor bytes allocated by PyTorch (excluding cached allocator pools and runtime context) and $\text{VRAM}_{\text{base}}$ stays constant for a fixed model and sequence length, the difference $\text{VRAM}_{\text{opt}} = \text{VRAM}_{\text{peak}} - \text{VRAM}_{\text{base}}$ (alongside peak allocation isolated across \texttt{opt.step()} after forward activations $A_{\text{ctx}}$ are released) isolates the memory consumed by optimizer state buffers, transient workspaces, and any master weight copies~\cite{zhao2024galore,dettmers2022eightbit}.

\subsection{Two-Class Acceptance Criteria}
\noindent
Validation checkpoints are scored by held-out cross-entropy loss $\mathcal{L}_{\text{val}}$ (in nats), perplexity $\text{PPL}_{\text{held-out}}$, and (when comparing across tokenizers) Bits-Per-Byte (BPB):
\begin{equation}
    \mathcal{L}_{\text{val}} = \frac{1}{N_{\text{eval}}}\sum_{i=1}^{N_{\text{eval}}}\mathcal{L}_{\text{CE}}(x_i), \qquad \text{PPL}_{\text{held-out}} = \exp(\mathcal{L}_{\text{val}}), \qquad \text{BPB} = \frac{N_{\text{eval}}}{B_{\text{UTF8}}\ln 2}\mathcal{L}_{\text{val}},
\end{equation}
where $B_{\text{UTF8}}$ is the total UTF-8 byte length of the held-out evaluation text. Because single-buffer ($\approx 2\text{ B/param}$) and dual-buffer ($4$--$12\text{ B/param}$) optimizers target different hardware memory budgets~\cite{zhao2024galore,dettmers2022eightbit}, LSO-Eval v1.1.1 defines \textbf{Two-Class Acceptance Criteria} measured against Native BF16 AdamW~\cite{loshchilov2019adamw} and FP32 Master AdamW:

\begin{description}[style=unboxed, leftmargin=1.8em, itemsep=0.45em]
    \item[Class I. Dual-Buffer / Full-State Optimizers ($\ge 4$~bytes/param):] Optimizers that store both first- and second-moment buffers ($m_t, v_t$) pass Class I if they achieve \textbf{equal or lower held-out validation loss and perplexity} than Native BF16 AdamW at the same token budget ($\Delta\mathcal{L}_{\text{val}} \le 0.0$ and $\Delta\text{PPL}_{\text{held-out}} = \text{PPL}_{\text{cand}} - \text{PPL}_{\text{AdamW-BF16}} \le 0.0$), satisfy $\text{F}_1 \wedge \text{F}_2$ stability bounds, keep median isolated \texttt{opt.step()} time within $1.15\times$ of Native BF16 AdamW, and require no extra optimizer memory ($\Delta\text{VRAM}_{\text{opt}} \le 0.0\text{ GB}$ at $0.01\text{ GB}$ resolution).

    \item[Class II. Single-Buffer / Compressed-State Optimizers ($\le 2$~bytes/param):] Optimizers that drop the second-moment buffer $v_t$ (or compress state tensors) to fit larger models on limited VRAM pass Class II if they meet four conditions:
    \begin{enumerate}[label=(\alph*), leftmargin=1.8em, itemsep=0.25em]
        \item \textit{Update Ratio and Loss Stability ($\text{F}_1 \wedge \text{F}_2$):} Layer-wise update ratios stay within $R_{t,l} \in [10^{-7}, 0.10]$ with no unrecovered loss spikes.
        \item \textit{Consistent Validation Improvement:} Held-out validation loss and perplexity improve across evaluation checkpoints without late-stage divergence.
        \item \textit{Memory \& Step Efficiency:} Cuts isolated optimizer memory by at least $35.0\%$ ($\Delta\text{VRAM}_{\text{opt}} \le -35.0\%$) relative to Native BF16 AdamW and at least $70.0\%$ ($\Delta\text{VRAM}_{\text{opt}} \le -70.0\%$) relative to FP32 Master AdamW\footnote{For a pure single-buffer \texttt{bfloat16} state ($2\text{ B/param}$) on multi-billion-parameter models where fixed allocator rounding is negligible, the exact state savings reach $-50.0\%$ vs.\ Native BF16 AdamW ($4\text{ B/param}$) and $-83.3\%$ vs.\ FP32 Master AdamW ($12\text{ B/param}$). The $-35.0\%$ and $-70.0\%$ thresholds leave room for allocator block alignment on smaller models and hybrid or subspace compression schemes.}, while keeping median isolated \texttt{opt.step()} time within $1.15\times$ of Native BF16 AdamW and faster than FP32 Master AdamW.
        \item \textit{Bounded Compression Loss Gap:} The validation log-perplexity gap relative to two-buffer Native BF16 AdamW stays within the Stage III $\text{F}_3$ bound:
        \begin{equation}
            \Delta\mathcal{L}_{\text{val}} = \ln\!\left(\frac{\text{PPL}_{\text{cand}}}{\text{PPL}_{\text{AdamW-BF16}}}\right) \le 0.25\text{ nats}.
        \end{equation}
    \end{enumerate}
\end{description}

\section{V-Eval: Vision Model Benchmarks}
\noindent
Autoregressive language models only tell part of the optimization story. In computer vision, convolutional stems, batch and global response normalization, scaled weight standardization, heavily augmented Vision Transformers, and flow-matching generative models place very different demands on momentum dynamics and step clipping. \textbf{V-Eval} complements the language modeling stages with a dedicated vision suite spanning multiple spatial resolutions.

\subsection{Model Sources, Two-Track Structure, and Scale Setups}
\noindent
All V-Eval benchmarks use standard model definitions from open-source libraries---\texttt{timm} (PyTorch Image Models), \texttt{torchvision.models}, Hugging Face \texttt{transformers}, and the official \texttt{facebookresearch/SiT} repository.

V-Eval is organized into two tracks across two hardware scale setups:
\begin{enumerate}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Track V-A (Core --- Vision From-Scratch Training):} Trains five vision backbones (V-A1 through V-A5) from random initialization (\texttt{pretrained=False}, \texttt{seed=42}, or $\ge 3$ seeds when compute permits) in native \texttt{torch.bfloat16} across three image resolutions ($32 \times 32$, $128 \times 128$, and $224 \times 224$).
    \item \textbf{Track V-B (Optional --- Vision Downstream Fine-Tuning):} Fine-tunes pretrained backbones on object detection (V-B1) and fine-grained classification (V-B2) when extra compute is available. Track V-B tests whether an optimizer preserves pretrained features without suffering BF16 rounding underflow at small learning rates ($\eta \le 10^{-4}$).
\end{enumerate}

\noindent
\textbf{Standard Setup (Single-GPU) vs.\ Extended Setup (Multi-GPU / Cluster) in Vision:}
\begin{itemize}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Standard Setup (Single-GPU Default, Tables~\ref{tab:track_va}--\ref{tab:track_vb}):} Uses \textbf{CIFAR-100} ($50,000$ train / $10,000$ val images at $32^2$), \textbf{ImageWoof} ($9,469$ train / $3,925$ val images at $224^2$), \textbf{Mini-ImageNet} ($50,000$ train / $10,000$ val images at $128^2$), \textbf{CIFAR-10 flow matching} ($50,000$ train / $10,000$ val images at $32^2$, evaluated with FID@10k), \textbf{cppe-5} or \textbf{Pascal VOC 2007} ($480^2$) for detection, and \textbf{Oxford-IIIT Pet} ($3,680$ train / $3,669$ test images at $224^2$) for fine-grained transfer.
    \item \textbf{Extended Setup (Multi-GPU / Cluster):} For multi-GPU or TPU clusters~\cite{chen2023lion,brock2021nfnet,taniguchi2024adopt}, implementations may additionally run from-scratch and fine-tuning benchmarks on \textbf{Full ImageNet-1K} ($1.28\text{M}$ train / $50\text{k}$ val images across $1,000$ classes at $224^2$--$384^2$) or \textbf{ImageNet-21K}. Out-of-distribution (OOD) generalization is tested on \texttt{ImageNet-ReaL}, \texttt{ImageNet-V2}, \texttt{ImageNet-A}, \texttt{ImageNet-R}, and \texttt{ObjectNet} ($> 190,000$ evaluation images in total)~\cite{chen2023lion}, alongside \textbf{Full MS-COCO 2017} ($118\text{k}$ train / $5\text{k}$ val) for object detection and \textbf{FID@50k on ImageNet $256^2$} for generative models~\cite{ma2024sit}.
\end{itemize}

\subsection{Candidate and Baseline Optimizers and Parameter Grouping}
\noindent
To evaluate native \texttt{bfloat16} training (no master weights) alongside \texttt{float32} master-weight training across both two-buffer and single-buffer designs, every task in Track V-A and Track V-B compares six optimizer setups:

\begin{enumerate}[leftmargin=1.8em, itemsep=0.35em]
    \item \texttt{Candidate\_Class\_I} (\textbf{Class I Candidate --- 2-Buffer Native BF16}): Full-state candidate optimizer ($m_t, v_t, \ge 4\text{ B/param}$) executed in native \texttt{bfloat16} without \texttt{float32} master weights, using decoupled weight decay $\lambda_{\text{wd}} = 0.08$ for from-scratch training and $\lambda_{\text{wd}} = 0.05$ for fine-tuning.
    \item \texttt{Candidate\_Class\_II} (\textbf{Class II Candidate --- 1-Buffer Native BF16}): Single-buffer or compressed-state candidate optimizer ($\le 2\text{ B/param}$) executed in native \texttt{bfloat16} without \texttt{float32} master weights, using decoupled weight decay $\lambda_{\text{wd}} = 0.08$ for from-scratch training and $\lambda_{\text{wd}} = 0.05$ for fine-tuning.
    \item \texttt{AdamW\_Native\_BF16} (\textbf{Baseline 2-Buffer --- Native BF16}): \texttt{torch.optim.AdamW}~\cite{loshchilov2019adamw} configured with \texttt{betas=(0.9, 0.999)}, \texttt{eps=1e-8}, \texttt{weight\_decay=0.08} (From-Scratch) / \texttt{0.05} (Fine-Tuning), and \texttt{fused=True}, executed directly on \texttt{bfloat16} parameters (\texttt{use\_fp32\_master=False} in the benchmark harness).
    \item \texttt{AdamW\_FP32\_Master} (\textbf{Reference 2-Buffer --- BF16 + FP32 Master Copy}): Identical to \texttt{AdamW\_Native\_BF16}, wrapped with an explicit \texttt{float32} master weight copy in the harness (\texttt{use\_fp32\_master=True}).
    \item \texttt{Lion\_Native\_BF16} (\textbf{Baseline 1-Buffer --- Native BF16}): \texttt{SimpleLion}~\cite{chen2023lion} (Listing~\ref{lst:simplelion}), \texttt{betas=(0.9, 0.99)}, \texttt{weight\_decay=0.8} (matching effective shrinkage $\eta\lambda = 8 \times 10^{-5}$ in Track V-A), \texttt{use\_fp32\_master=False}.
    \item \texttt{Lion\_FP32\_Master} (\textbf{Reference 1-Buffer --- BF16 + FP32 Master Copy}): Identical to \texttt{Lion\_Native\_BF16}, wrapped with an explicit \texttt{float32} master weight copy in the harness (\texttt{use\_fp32\_master=True}).
\end{enumerate}

\noindent
\textbf{Weight Decay Parameter Grouping (\texttt{split\_vision\_parameter\_groups}):} Across all six optimizers in V-Eval (as well as LLM and hybrid runs in Stages III and IV), model parameters are partitioned into two groups before training (see Listing~\ref{lst:simplelion} for the complete keyword list):
\begin{itemize}[leftmargin=1.8em, itemsep=0.35em]
    \item \textbf{Decayed Group ($\lambda_{\text{wd}} > 0$):} All weight matrices and convolutional kernels with at least two non-singleton dimensions ($\text{ndim} \ge 2$, excluding singleton-broadcasted vectors with $\text{ndim} > 2$ and \texttt{param.squeeze().ndim} $\le 1$), including standard and depthwise convolutions, linear projections, attention matrices, MLP weights, and token embeddings (unless excluded via \texttt{exclude\_embeddings=True}).
    \item \textbf{No-Decay Group ($\lambda_{\text{wd}} = 0.0$):}
    \begin{enumerate}[label=(\alph*), leftmargin=1.8em, itemsep=0.25em]
        \item \textit{0D/1D and Singleton-Broadcasted Tensors:} Biases, 1D affine scales and shifts, and channel- or head-wise vectors stored with singleton broadcast dimensions (such as $(1, 1, 1, C)$ GRN parameters in ConvNeXt-V2 or $(1, C, 1, 1)$ channel scales where $\text{ndim} > 2$ and \texttt{param.squeeze().ndim} $\le 1$).
        \item \textit{Normalization, Scaling \& Temperature Parameters:} Parameters belonging to normalization layers (\texttt{BatchNorm}, \texttt{LayerNorm}, \texttt{RMSNorm}~\cite{zhang2019rmsnorm}, \texttt{GroupNorm}, \texttt{GRN}, \texttt{RaNorm}/\texttt{L1Norm}, and attention \texttt{QK-Norm}), residual scaling gains (\texttt{LayerScale}, Dynamic Tanh \texttt{DyT}~\cite{zhu2025dyt}, and NF-Net skip gains~\cite{brock2021nfnet}), and learnable attention or contrastive temperature scalars (\texttt{logit\_scale}, \texttt{head\_scale}).
        \item \textit{Positional, Register \& Query Tables:} Structural tokens (\texttt{cls\_token}, \texttt{reg\_token}, \texttt{mask\_token}), absolute and relative positional embeddings (\texttt{pos\_embed}, relative bias tables, and rotary frequencies~\cite{su2024roformer}), and object detection query tables (\texttt{query\_embed}, \texttt{query\_pos}).
        \item \textit{Sequence-Model Decay Parameters, MoE Biases \& Custom Hooks:} State-space and linear-attention decay parameters in Mamba, GLA~\cite{yang2024gla}, and RWKV (\texttt{A\_log}, \texttt{dt\_bias}, 1D skip vector \texttt{D}, \texttt{time\_decay}), router bias terms in Mixture-of-Experts models, and any parameter marked via \texttt{no\_weight\_decay()} model hooks.
    \end{enumerate}
\end{itemize}

\noindent
\textbf{Baseline Parameter Alignment and Effective Weight Decay (v1.1.1):} For vision benchmarks in LSO-Eval v1.1.1, the \texttt{SimpleLion} baseline uses $\beta = (0.9, 0.99)$ and decoupled weight decay $\lambda = 0.8$ (Listing~\ref{lst:simplelion}), following the vision settings and hyperparameter scaling rule in Chen et al.~\cite{chen2023lion} (Section 3.2 and Appendix M). Because decoupled weight decay multiplies weights by $(1 - \eta\lambda)$ at each step and Lion operates at a $10\times$ smaller learning rate ($\eta_{\text{Lion}} = 10^{-4}$) than AdamW ($\eta_{\text{AdamW}} = 10^{-3}$), setting $\lambda_{\text{Lion}} = 0.8$ keeps per-step weight shrinkage identical across baselines:
\begin{equation}
    \eta_{\text{Lion}} \cdot \lambda_{\text{Lion}} = 10^{-4} \times 0.8 = 8 \times 10^{-5} = 10^{-3} \times 0.08 = \eta_{\text{AdamW}} \cdot \lambda_{\text{AdamW}}.
\end{equation}

\begin{lstlisting}[caption={Standard LSO-Eval V-Eval: Vectorized PyTorch SimpleLion Optimizer (Chen et al., NeurIPS 2023, Algorithm 2) \& Decoupled Parameter Grouping}, label={lst:simplelion}]
from collections import defaultdict
import torch
import torch.nn as nn

class SimpleLion(torch.optim.Optimizer):
    def __init__(self, params, lr=1e-4, betas=(0.9, 0.99), weight_decay=0.8,
                 foreach=True, use_fp32_master=False):
        if lr < 0.0:
            raise ValueError(f"Invalid learning rate: {lr}")
        if not 0.0 <= betas[0] < 1.0:
            raise ValueError(f"Invalid beta parameter at index 0: {betas[0]}")
        if not 0.0 <= betas[1] < 1.0:
            raise ValueError(f"Invalid beta parameter at index 1: {betas[1]}")
        if weight_decay < 0.0:
            raise ValueError(f"Invalid weight_decay value: {weight_decay}")
        defaults = dict(
            lr=lr, betas=betas, weight_decay=weight_decay,
            foreach=foreach, use_fp32_master=use_fp32_master
        )
        super().__init__(params, defaults)

    @torch.no_grad()
    def step(self, closure=None):
        loss = None
        if closure is not None:
            with torch.enable_grad():
                loss = closure()
        for group in self.param_groups:
            lr = group["lr"]
            beta1, beta2 = group["betas"]
            wd = group["weight_decay"]
            use_foreach = group.get("foreach", True)
            use_master = group.get("use_fp32_master", False)
            buckets = defaultdict(lambda: ([], [], [], []))

            for p in group["params"]:
                if p.grad is None:
                    continue
                grad = p.grad
                if grad.is_sparse:
                    raise RuntimeError("SimpleLion does not support sparse grads.")
                state = self.state[p]
                if len(state) == 0:
                    stat_dtype = torch.float32 if use_master else p.dtype
                    state["exp_avg"] = torch.zeros_like(
                        p, dtype=stat_dtype, memory_format=torch.preserve_format
                    )
                    if use_master and p.dtype != torch.float32:
                        state["master_param"] = p.detach().float().clone()
                work_p = state.get("master_param", p)
                work_g = grad.to(dtype=work_p.dtype) if grad.dtype != work_p.dtype else grad
                key = (work_p.device, work_p.dtype)
                buckets[key][0].append(work_p)
                buckets[key][1].append(work_g)
                buckets[key][2].append(state["exp_avg"])
                buckets[key][3].append(p)

            for (_, _), (work_params, grads, exp_avgs, orig_params) in buckets.items():
                if use_foreach:
                    if wd != 0.0:
                        torch._foreach_mul_(work_params, 1.0 - lr * wd)
                    updates = torch._foreach_lerp(exp_avgs, grads, 1.0 - beta1)
                    torch._foreach_sign_(updates)
                    torch._foreach_add_(work_params, updates, alpha=-lr)
                    torch._foreach_lerp_(exp_avgs, grads, 1.0 - beta2)
                else:
                    for wp, g, m in zip(work_params, grads, exp_avgs):
                        if wd != 0.0:
                            wp.mul_(1.0 - lr * wd)
                        u = m.lerp(g, 1.0 - beta1).sign_()
                        wp.add_(u, alpha=-lr)
                        m.lerp_(g, 1.0 - beta2)
                if use_master:
                    pairs = [(p_o, wp) for p_o, wp in zip(orig_params, work_params) if p_o is not wp]
                    if pairs:
                        if use_foreach:
                            torch._foreach_copy_([x[0] for x in pairs], [x[1] for x in pairs])
                        else:
                            for p_o, wp in pairs:
                                p_o.copy_(wp)
        return loss

    def load_state_dict(self, state_dict):
        super().load_state_dict(state_dict)
        for group in self.param_groups:
            if group.get("use_fp32_master", False):
                for p in group["params"]:
                    st = self.state.get(p, {})
                    for k in ("master_param", "exp_avg"):
                        if k in st and st[k].dtype != torch.float32:
                            st[k] = st[k].to(dtype=torch.float32)

def split_vision_parameter_groups(model: nn.Module, weight_decay: float = 0.08,
                                  exclude_embeddings: bool = False):
    no_decay_substr = (
        "bias", "norm", "rmsnorm", "groupnorm", "ranorm", "l1norm",
        "global_response_norm", "q_norm", "k_norm", "qk_norm", "layerscale",
        "gamma", "beta", "dynamic_tanh", "alpha", "gain", "skipinit",
        "logit_scale", "logit_bias", "head_scale", "cpb_mlp",
        "cls_token", "reg_token", "register_token", "dist_token", "mask_token",
        "pos_embed", "positional_embedding", "class_embedding",
        "absolute_pos_embed", "relative_position_bias_table", "rel_pos",
        "rope", "freqs_cis", "query_embed", "query_pos", "level_embed",
        "a_log", "dt_bias", "d_skip", "time_mix", "time_decay", "time_first",
        "e_score_correction_bias", "expert_bias",
    )
    no_decay_tokens = {"bn", "ln", "grn", "ls1", "ls2", "dyt"}
    if exclude_embeddings:
        no_decay_substr = no_decay_substr + (
            "tok_embeddings", "embed_tokens", "word_embeddings"
        )
        no_decay_tokens.add("wte")

    has_nwd = hasattr(model, "no_weight_decay") and callable(model.no_weight_decay)
    explicit_no_decay = set(model.no_weight_decay()) if has_nwd else set()

    has_kw = (
        hasattr(model, "no_weight_decay_keywords")
        and callable(model.no_weight_decay_keywords)
    )
    keyword_no_decay = (
        tuple(k.lower() for k in model.no_weight_decay_keywords())
        if has_kw else ()
    )

    decay, no_decay = [], []
    for name, param in model.named_parameters():
        if not param.requires_grad:
            continue
        lname = name.lower()
        segments = {
            seg.rstrip("0123456789")
            for seg in lname.replace(".", "_").split("_")
        }
        if (
            param.ndim <= 1
            or (param.ndim > 2 and param.squeeze().ndim <= 1)
            or getattr(param, "_no_weight_decay", False)
            or getattr(param, "no_weight_decay", False)
            or name in explicit_no_decay
            or bool(segments & no_decay_tokens)
            or any(k in lname for k in no_decay_substr)
            or any(k in lname for k in keyword_no_decay)
        ):
            no_decay.append(param)
        else:
            decay.append(param)
    return [
        {"params": decay, "weight_decay": float(weight_decay)},
        {"params": no_decay, "weight_decay": 0.0},
    ]
\end{lstlisting}

\subsection{Track V-A: Vision From-Scratch Evaluation (Core)}
\noindent
Every Track V-A model is trained from random initialization (\texttt{pretrained=False}, \texttt{seed=42}) in \texttt{torch.bfloat16} on a single GPU (reference hardware: $1\times$ NVIDIA A100 40~GB). Evaluating ImageNet-stem ConvNets solely on $32 \times 32$ CIFAR images collapses their final feature maps to $1 \times 1$. To test spatial feature maps properly while keeping compute reasonable, Track V-A spans three image resolutions using standard ImageNet subsets alongside CIFAR (Table~\ref{tab:track_va}). Classification tasks (V-A1 through V-A4) are scored by \textbf{Top-1 Accuracy (\%)}, \textbf{Top-5 Accuracy (\%)}, and \textbf{Validation Cross-Entropy Loss ($\mathcal{L}_{\text{val}}$)}:

\begin{enumerate}[label=\textbf{V-A\arabic*.}, leftmargin=3.2em, itemsep=0.45em]
    \item \textbf{Residual CNN (\texttt{ResNet-50}~\cite{he2016resnet}, CIFAR $3 \times 3$ stem, $\approx 23.7\text{M}$ params):} Standard residual network with \texttt{BatchNorm2d} and \texttt{ReLU} trained on \textbf{CIFAR-100} ($32 \times 32$, $50,000$ train / $10,000$ val images, $100$ classes)~\cite{loshchilov2019adamw,zhuang2020adabelief,zhang2019lookahead}, using the \texttt{timm} \texttt{resnet50} backbone modified with a $3 \times 3$ CIFAR stem.

    \item \textbf{Normalization-Free CNN (\texttt{NF-ResNet-50}~\cite{brock2021nfnet}, $\approx 25.6\text{M}$ params):} Replaces batch normalization with Scaled Weight Standardization (\texttt{ScaledStdConv2d}) and trains at full $224 \times 224$ resolution on \textbf{ImageWoof} ($10$ fine-grained dog breed classes from ImageNet, $9,469$ train / $3,925$ val images) using the \texttt{timm} \texttt{nf\_resnet50} model. With $\sim 9.5\text{k}$ training images ($3,600$ steps per $100$ epochs at \texttt{batch\_size=256} with \texttt{drop\_last=True}), ImageWoof tests full $224 \times 224$ feature maps at roughly one-fifth the step count of CIFAR-100.

    \item \textbf{Depthwise ConvNet (\texttt{ConvNeXt-V2-Tiny}~\cite{woo2023convnextv2}, $\approx 28.6\text{M}$ params):} Combines $7 \times 7$ depthwise convolutions, \texttt{LayerNorm}, and Global Response Normalization (GRN) under Mixup ($0.8$), CutMix ($1.0$), and Label Smoothing ($0.1$) on \textbf{Mini-ImageNet} ($128 \times 128$, $100$ ImageNet classes, $50,000$ train / $10,000$ val images)~\cite{liang2026cautious} via \texttt{timm} \texttt{convnextv2\_tiny}. At $128 \times 128$ resolution, the final stage preserves a $4 \times 4$ feature grid for the $7 \times 7$ depthwise kernels with the same step count as CIFAR-100 ($19,500$ steps over $100$ epochs).

    \item \textbf{Vision Transformer (\texttt{ViT-Small}~\cite{dosovitskiy2021vit}, Patch $8 \times 8$, $\approx 22.0\text{M}$ params):} Multi-head self-attention backbone trained on \textbf{Mini-ImageNet} ($128 \times 128$, $100$ classes, $50,000$ train / $10,000$ val images) following the Mini-ImageNet ViT setup in Liang et al.~\cite{liang2026cautious}. Uses the \texttt{timm} \texttt{vit\_small\_patch16\_224} architecture configured for $128 \times 128$ inputs and $8 \times 8$ patches ($256$ tokens per image) under RandAugment, Mixup ($0.8$), CutMix ($1.0$), and Label Smoothing ($0.1$).

    \item \textbf{Flow-Matching Generative Model (\texttt{SiT-S/2}~\cite{ma2024sit,lipman2023flow}, $\approx 33.0\text{M}$ params):} Scalable Interpolant Transformer trained with Rectified Flow Matching velocity MSE loss ($\mathcal{L}_{\text{FM}} = \mathbb{E}_{t,x_0,x_1}[\|v_\theta(x_t, t) - (x_1 - x_0)\|_2^2]$ and Model EMA $0.999$) on \textbf{CIFAR-10} ($32 \times 32$, $50,000$ train / $10,000$ val images). Evaluated by held-out \textbf{Velocity MSE Loss ($\mathcal{L}_{\text{FM}}$)} on the $10,000$ validation images and \textbf{Fr\'echet Inception Distance (FID@10k)} from $10,000$ ODE-sampled images (using a 50-step Heun/Euler solver on the $0.999$ EMA weights; FID@50k in the Extended Setup).
\end{enumerate}

\noindent
\textbf{Epoch Budget, Deterministic Shuffling, and Validation Schedule:} Track V-A allows $50$--$150$ epochs for CNNs (V-A1, V-A2) and $50$--$200$ epochs for ConvNeXt, ViT, and SiT (V-A3--V-A5), with a \textbf{standard default of 100 epochs} ($19,500$ steps for V-A1/A3/A4/A5; $3,600$ steps for V-A2) at \texttt{batch\_size = 256}. Training loaders shuffle sample indices each epoch using a deterministic generator seeded with \texttt{seed + epoch} and drop incomplete trailing batches, ensuring that all six optimizers see the same sequence of mini-batches $(x_t, y_t)$ without class-order bias in \texttt{BatchNorm2d} or Mixup/CutMix. Every optimizer runs for the same epoch count $E$ under linear warmup ($5\%$ of $E$ for V-A1/A2/A5; $10\%$ of $E$ for V-A3/A4) followed by cosine decay to $\eta_{\min} = 0.05\eta$. Validation runs every $10\%$ of total epochs and at the end of training over the full validation split, logging accuracy and loss alongside median step time (ms) and throughput (images/sec).

\subsection{Track V-B: Downstream Fine-Tuning (Optional)}
\noindent
Track V-B is an optional suite for evaluating transfer learning from pretrained weights at small learning rates ($\eta \le 10^{-4}$). At these step sizes, unrounded \texttt{bfloat16} additions can round to zero whenever $|\Delta\theta_{t,i}| = |\eta_t\delta_{t,i}| < \frac{1}{2}\text{ULP}(\theta_{t,i})$~\cite{zamirai2021revisiting}, whereas poorly scaled updates can degrade pretrained features (Table~\ref{tab:track_vb}):

\begin{enumerate}[label=\textbf{V-B\arabic*.}, leftmargin=3.2em, itemsep=0.45em]
    \item \textbf{Object Detection Fine-Tuning (\texttt{RT-DETR-R18} / \texttt{YOLOv11-S} / \texttt{FCOS-ResNet50}):}
    \begin{itemize}[leftmargin=1.5em, itemsep=0.25em]
        \item \textit{Setup \& Dataset:} Pretrained COCO or ImageNet backbone paired with a newly initialized detection head on \textbf{cppe-5} ($5$ classes, $480 \times 480$) or \textbf{Pascal VOC 2007} ($20$ classes, $480 \times 480$; or \textbf{MS-COCO 2017} $118\text{k}$ train / $5\text{k}$ val in Extended Setup).
        \item \textit{Schedule \& Learning Rates:} $15$--$35$ epochs (\textbf{default 25 epochs}), \texttt{batch\_size = 16} (or $32$), 2-epoch linear warmup followed by cosine decay. Learning rates: Candidate $\eta \in \{1 \times 10^{-4}, 2 \times 10^{-4}\}$, AdamW $\eta = 1 \times 10^{-4}$, Lion $\eta = 3 \times 10^{-5}$.
        \item \textit{Loss \& Metrics:} Hungarian bipartite matching / multi-task bounding-box loss ($\text{Focal} + L_1 + \text{GIoU}$), scored every 5 epochs by \textbf{COCO $\text{mAP}_{50:95}$ (\%)} (mean Average Precision averaged over IoU thresholds $0.50:0.05:0.95$), \textbf{$\text{mAP}_{50}$ (\%)} (AP at $\text{IoU} = 0.50$), and \textbf{Validation Box Loss}.
    \end{itemize}

    \item \textbf{Fine-Grained Classification Fine-Tuning (\texttt{ViT-Base/16} \& \texttt{ConvNeXt-Base}):}
    \begin{itemize}[leftmargin=1.5em, itemsep=0.25em]
        \item \textit{Setup \& Dataset:} Pretrained ImageNet-1K backbone (\texttt{timm}) with a new linear classification head on \textbf{Oxford-IIIT Pet} ($37$ classes, $3,680$ train / $3,669$ test images at $224 \times 224$)~\cite{chen2023lion}.
        \item \textit{Schedule \& Learning Rates:} $10$--$30$ epochs (\textbf{default 20 epochs}), \texttt{batch\_size = 64}, 2-epoch linear warmup followed by cosine decay. Learning rates: Candidate $\eta = 1 \times 10^{-4}$, AdamW $\eta = 1 \times 10^{-4}$, Lion $\eta = 3 \times 10^{-5}$.
        \item \textit{Metrics:} \textbf{Top-1 Accuracy (\%)}, \textbf{Top-5 Accuracy (\%)}, and \textbf{Validation Cross-Entropy Loss} measured every 2 epochs across all $3,669$ test images.
    \end{itemize}
\end{enumerate}

\subsection{Acceptance Criteria for Vision (V-Eval)}
\noindent
Consistent with Stage IV, V-Eval evaluates candidates under two memory classes against the two-buffer baselines (\texttt{AdamW\_Native\_BF16} and \texttt{AdamW\_FP32\_Master}) and single-buffer baselines (\texttt{Lion\_Native\_BF16} and \texttt{Lion\_FP32\_Master}), where $\Delta X = X_{\text{cand}} - X_{\text{ref}}$:

\begin{description}[style=unboxed, leftmargin=1.8em, itemsep=0.45em]
    \item[Class I. Dual-Buffer / Full-State Optimizers (\texttt{Candidate\_Class\_I}):] Passes Class I if update ratios and loss curves stay within $\text{F}_1 \wedge \text{F}_2$ bounds ($R_{t,l} \in [10^{-7}, 0.10]$ without unrecovered spikes), isolated optimizer VRAM does not exceed \texttt{AdamW\_Native\_BF16} ($\Delta\text{VRAM}_{\text{opt}} \le 0.0\text{ GB}$ at $0.01\text{ GB}$ resolution), median isolated \texttt{opt.step()} time stays within $1.15\times$ of \texttt{AdamW\_Native\_BF16}, and validation quality matches or exceeds \texttt{AdamW\_Native\_BF16} on the target task:
    \begin{equation}
        \begin{gathered}
            \Delta\text{Acc}_{\text{Top-1}} \ge 0.0\%, \quad \Delta\text{Acc}_{\text{Top-5}} \ge -0.2\%, \quad \Delta\text{mAP}_{50:95} \ge 0.0\%, \\
            \Delta\mathcal{L}_{\text{FM}} \le 0.0, \quad \Delta\text{FID} \le 0.0.
        \end{gathered}
    \end{equation}

    \item[Class II. Single-Buffer / Compressed-State Optimizers (\texttt{Candidate\_Class\_II}):] Passes Class II if it satisfies $\text{F}_1 \wedge \text{F}_2$ stability, cuts isolated optimizer memory by at least $35.0\%$ compared to \texttt{AdamW\_Native\_BF16} and at least $70.0\%$ compared to \texttt{AdamW\_FP32\_Master} while staying within $+10.0\%$ of single-buffer \texttt{Lion\_Native\_BF16}:
    \begin{equation}
        \begin{gathered}
            \Delta\text{VRAM}_{\text{opt}}^{(\text{vs.\ AdamW-BF16})} \le -35.0\%, \quad \Delta\text{VRAM}_{\text{opt}}^{(\text{vs.\ AdamW-FP32})} \le -70.0\%, \\
            \Delta\text{VRAM}_{\text{opt}}^{(\text{vs.\ Lion-BF16})} \le +10.0\%,
        \end{gathered}
    \end{equation}
    keeps median isolated \texttt{opt.step()} time within $1.15\times$ of \texttt{AdamW\_Native\_BF16} (and faster than \texttt{AdamW\_FP32\_Master}), remains within $\Delta\mathcal{L}_{\text{val}} \le 0.25$ nats (or $-1.5\%$ Top-1 accuracy) of two-buffer \texttt{AdamW\_Native\_BF16}, and matches or outperforms single-buffer \texttt{Lion\_Native\_BF16} ($\Delta\text{Acc}_{\text{Top-1}}^{(\text{vs.\ Lion-BF16})} \ge 0.0\%$ or $\Delta\mathcal{L}_{\text{val}}^{(\text{vs.\ Lion-BF16})} \le 0.05$ nats).
\end{description}
